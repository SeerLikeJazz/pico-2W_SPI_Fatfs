# Pico2W_EEG 二进制协议 V2（无 CRC）

服务端为 Pico 2 W，开放调试热点 `Pico2W_EEG`，DHCP 分配地址，上位机连接 `192.168.4.1:5000`。只接受一个 TCP 数据客户端；后续连接被终止。上电及 TCP 建连后均保持待机，须通过独立控制端口显式 START；采集开始后数据自动发送。数据端口仅接收心跳，不解释采样控制命令。独立 TCP 5001 WFC2 模式/参数/启停协议及上位机说明见 [Code/README.md](../../Code/README.md)，控制协议仍为 WFC2；数据协议版本字节现为 2。

本版本采用持续 TCP 字节流、二进制组包和 lwIP COPY 发送。**1024 字节是应用包长度，不是 TCP 报文、无线帧或一次 recv 的长度。** 接收端必须累积字节，处理拆包、粘包和重新同步。

## 包结构

包长度固定 1024：44 字节头 + 972 字节数据 + 4 字节保留零 + 4 字节尾。除 ADS 原始帧外，多字节整数字段均为小端序。固件逐字段编码，不发送 C 结构体内存。

| 偏移 | 字节数 | 字段 | 定义 |
| --- | --- | --- | --- |
| 0 | 4 | magic | ASCII EEG1：45 45 47 31 |
| 4 | 1 | version | 2 |
| 5 | 1 | packet_type | 1，采样数据 |
| 6 | 2 | flags | 见下表 |
| 8 | 2 | packet_length | 1024 |
| 10 | 2 | header_length | 44 |
| 12 | 2 | sample_count | 1～36 |
| 14 | 2 | sample_size | 27 |
| 16 | 4 | packet_sequence | 本采集代次内的包序号 |
| 20 | 4 | first_sample_sequence | 首帧软件 DRDY 序号 |
| 24 | 8 | first_sample_timestamp_us | 首帧 MCU DRDY 中断时间，微秒 |
| 32 | 4 | ads_mclk_hz | 配置的 ADS 主时钟频率 |
| 36 | 2 | nominal_sample_rate | 在 2.048 MHz 时钟下的标称 SPS |
| 38 | 1 | gain | 实际增益：1、2、4、6、8、12、24 |
| 39 | 1 | mode | 0 内部测试；1 内部短接；2 正常输入；3 阻抗交流激励原始码 |
| 40 | 4 | stream_id | 采集代次 |
| 44 | 972 | samples | 最多 36 个原始帧，不足部分全部补零 |
| 1016 | 4 | reserved | 全部为零，不计算或校验 CRC |
| 1020 | 4 | tail | 固定 0D 0A A5 5A |

| flags 位 | 含义 |
| --- | --- |
| bit0 | 本包不足 36 帧，空余数据区补零 |
| bit1 | 新采集代次首个生成的数据包 |
| bit2 | 相对同代次前一生成包，首采样序号不连续 |
| bit3 | 主时钟频率仍是未经实测确认的配置假设 |
| bit4～15 | 本版写 0，接收端忽略未知位以便扩展 |

每个 ADS 原始帧为状态字 3 字节，然后 CH1～CH8 各 3 字节；全部保持 ADS 输出的高字节在前顺序。状态高 4 位正常应为 0xC。通道为 24 位二补码，例如 `7F FF FF`=8388607、`80 00 00`=-8388608、`FF FF FF`=-1。传输的是原始码，不是微伏。

## 连续性、代次与时间

包内所有帧必须序号连续、配置相同、stream_id 相同。遇到序号缺口或配置/代次变化，先结束旧包、补零，再开始新包。序号均按 uint32 模 2^32 自然回绕；FFFFFFFF 后的 00000000 是连续的。

Core 0 启动时以 `get_rand_32()` 生成种子，每次实际启动采集时递增，作为 stream_id。STOP/START、模式切换、需要停采的寄存器读回、自动恢复后的重新启动均产生新代次。随机种子降低重启碰撞概率，但 **32 位 stream_id 不是跨设备、跨重启的全球唯一标识**。接收程序以连接编号另外区分 TCP 会话，重连后重设连续性基线，不能据此计算断网期间的全部损失。

每个新代次的第一个生成包从 packet_sequence=0 开始，随后按 uint32 递增。已生成但断线丢弃的包不会重用序号；尚未封装的非空组包在断线丢弃时也占用一个序号，并计入丢弃统计。因此接收端可能首次看到非零包序号、且没有 bit1。bit2 相对前一**生成包**计算；接收端仍须独立比较所收到的包序号和采样序号，不能只依赖 flags 判定丢失。

时间戳来自 MCU 处理首帧 DRDY 中断的时刻，不是 UTC，也不是 ADC 内部精确转换时刻。其他帧没有独立传输实测时间戳，只能估算：

```text
配置推导采样率 = nominal_sample_rate × ads_mclk_hz / 2048000
估算第 i 帧时间 = first_sample_timestamp_us + i × 1000000 / 配置推导采样率
第 i 帧序号 = (first_sample_sequence + i) mod 2^32
```

主时钟假设或实测误差会影响此估算；配置推导值不等于软件实测帧率。软件 DRDY 序号无法识别 MCU 完全未观察到的硬件 DRDY 边沿，零缺口不能证明硬件无漏帧。

## 无 CRC 与分包

V2 不计算应用层 CRC。保留原 1024 字节布局，1016～1019 为保留零，版本字节改为 2；旧 V1 接收端必须同步升级，新接收端明确拒绝 V1。文件路径暂保留 PROTOCOL_V1.md 以兼容已有文档链接，本文和示例内容均为 V2。

接收步骤：搜索 magic → 验证头字段 → 等待满 1024 字节 → 检查固定位置包尾、补零区和保留零 → 交付样本。候选包错误时仅跳过一个字节重搜。原始采样载荷中的位错误不再由应用层检测；序号仍用于检测缺口。TCP 校验不能检测 SPI 采集阶段已经发生的数据错误。

## 组包、带宽与缓存

通常每 36 帧一包；250 SPS 下包间隔约 144 ms，第一帧等到第 36 帧约 140 ms。组包器从第一帧进入组包缓冲开始计时，最长等待默认 200 ms。满包、超时、显式停采、配置变化或缺口会触发封装；没有样本不发空包。**200 ms 是组包触发期限，不是网络交付上限**；已有待发包被背压阻塞时，需要先腾出待发缓冲。

每包有效数据占 972/1024=94.921875%。250 SPS 连续满包时，ADS 原始数据约 6750 B/s，应用协议约 7111 B/s，另有 TCP/IP 和无线开销。高采样率时带宽线性增长，实际无线吞吐必须测量。

Core 0 的 ADS 本地队列仍独立存在。新增跨核队列 512 项，每项 56 字节，含原始帧和元数据；连同原子计数占 **28696 字节**。默认 250 SPS 容纳约 2.048 秒；16000 SPS 仅约 32 ms。Core 1 另有 1024 字节组包区和 1024 字节待发区，两个缓冲通过指针交换角色，不进行整包复制；状态大小依 ABI 而定。

跨核队列采用单生产者/单消费者原子 acquire/release：Core 0 只推进 head，Core 1 只推进 tail；队满时丢弃新网络样本，原采集及 USB 不等待。无 TCP 客户端时持续消费丢弃；新连接清理连接前积压。断线清理待发半包、当前组包及队列快照，下一连接不会从旧包中间开始。

显式 STOP 通过原子停止游标/事件计数传递，不占样本槽，因此队满也不会丢失最终停止通知。多个快速 STOP 可以合并；样本携带代次信息，保证中间代次不被混入同一包。

TCP 使用 `TCP_WRITE_FLAG_COPY`，仅成功复制的字节推进发送偏移；sndbuf 不足或 ERR_MEM 保留原位置。前一包未全部排入 lwIP 前不能插入下一包。tcp_output 重试不重复 tcp_write。应用已批量组包，因此关闭 Nagle，减少额外等待；不逐包等待 ACK。

“组包完成”“字节排入 TCP”“字节获 TCP ACK”是三个不同阶段。ACK 只说明对端 TCP 栈确认，不能证明上位机程序已解析或保存。断线时已入队但未 ACK 的字节可能有部分已经到达；固件不能精确判断这些字节在对端应用中的命运。
