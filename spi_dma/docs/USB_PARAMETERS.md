# USB 动态采样率和增益

在 USB CDC 串口终端输入冒号命令后按 Enter：

```text
:rate 1000
:gain 24
```

**冒号是必需的。** 原有 `r` 立即读寄存器，`g` 立即启动；新增命令必须以 `:` 进入行输入模式，避免前缀冲突。不要直接输入没有冒号的 `rate` 或 `gain`，它们会被当成旧的单字符命令序列。终端可启用本地回显；固件不逐字符回显。

| 命令 | 合法参数 | 作用 |
| --- | --- | --- |
| `:rate SPS` | 250、500、1000、2000、4000、8000、16000 | 修改标称 SPS，保留增益、模式、SRB、BIAS |
| `:gain N` | 1、2、4、6、8、12、24 | 全部 8 通道统一实际增益倍数，保留其他配置 |

数值为十进制整数，不支持 `1k`、`16k`、正负号、小数或额外参数。支持空格、Tab、CR、LF、CRLF、退格 Backspace/DEL，以及分多轮到达的字符。单行最多 47 字节（不含冒号和换行）；超长后整行丢弃至换行，报告一次错误，下一条可正常输入。空行忽略。每次主循环最多取 16 个字符、执行一条命令，不等待用户输完整行；换行后配置事务本身包含原有的有界停止等待、寄存器访问和 150 ms 参考稳定等待。

现有 `? s r p x g i t h n` 命令仍即时执行，启用 SD 构建时也保留 `b`。`?` 显示完整新语法；网络 TCP 不接受配置命令。

## 应用流程与状态

1. 在 Core 0 读取当前已验证配置及运行状态；硬件未初始化、配置无效或 fatal 时拒绝本命令，使用 `i` 显式重试初始化。
2. 校验参数、外部主时钟范围、SPI 分频和带宽；可预检失败发生在停采之前。
3. 相同值返回 `UNCHANGED`，不停止、不更新采集代次。
4. 运行时安全停采，禁用 DRDY/DMA 触发并处理在途传输；在停止状态调整 SPI、写 ADS 寄存器并读回校验。原来已停止则直接配置并继续保持停止。
5. 读回成功才提交 RAM 配置；原来运行时再调用现有 START 流程，输出 `APPLIED` 或具体失败原因。

若寄存器写入/读回失败，不自动盲目回滚部分已写入的寄存器，不启动采集。RAM 保留最后一次验证成功的配置供 `i` 重试，日志显示 `configured=0`、`INVALID hardware config; RAM retry target`。若新配置已读回成功、但重新 START 失败，RAM 保留新配置用于重试，并报告最终配置有效性及停止状态。DMA 无法安全终止时标为 fatal，不能复用可能仍被硬件访问的缓存。

成功/失败响应包含操作、旧值、请求值、配置有效性、运行状态及错误名称；随后输出实际已验证配置（或明确标注的 RAM 重试目标）、模式、增益、标称/推导采样率、实际 SPI 频率及寄存器校验信息。日志仍使用有界 USB 队列，日志丢弃与采样丢弃统计独立。

配置仅在 RAM 中有效；断电后回到 `ads1299_config.h` 默认值，不写 Flash。`i` 按当前 RAM 配置执行重置/配置/启动，不会把成功设置过的参数强制还原为编译默认值。

## 高采样率 SPI 调速

采样率通过 ADS CONFIG1 的 DR 编码设置；SPI 调速仅提供读出带宽。推导采样率为：

```text
标称 SPS × ADS_MCLK_HZ / 2048000
```

默认保守 SPI 基准 `ADS_SPI_HZ=1000000`，上限 `ADS_SPI_MAX_HZ=8000000`。请求依次尝试基准、2 倍、4 倍，直到上限；采用能使 216 位传输时间严格小于采样周期 75% 的最低候选档，保留至少 25% 周期给软件和数据更新裕量。该裕量并不保证任何中断负载下都无漏帧。

预检用本机 SDK 2.2.0 PL022 整数分频规则预测实际 SPI；停采后调用 `spi_set_baudrate()`，再次使用 SDK 返回值校验。清 FIFO/外设复位路径保留选择的请求速率，防止 START 或后续恢复时意外降回 1 MHz。

以 MCLK=2.048 MHz、clk_peri=150 MHz 为例（以启动日志实际频率为准）：

| 标称 SPS | 采样周期 µs | SPI 请求 Hz | SPI 实际 Hz（整数返回值） |
| --- | ---: | ---: | ---: |
| 250 | 4000 | 1000000 | 1000000 |
| 500 | 2000 | 1000000 | 1000000 |
| 1000 | 1000 | 1000000 | 1000000 |
| 2000 | 500 | 1000000 | 1000000 |
| 4000 | 250 | 2000000 | 1973684 |
| 8000 | 125 | 4000000 | 3947368 |
| 16000 | 62.5 | 8000000 | 7500000 |

当前规划器要求配置的 MCLK 满足 [TI ADS1299 Rev C 表 7.6](https://www.ti.com/lit/ds/symlink/ads1299.pdf) 的 414～666 ns 周期范围。该表给出不同 DVDD 下 SCLK 最小周期 50/66.6 ns；本工程默认 8 MHz 上限，配置允许的绝对上限为 10 MHz，均留有裕量。控制事务保留显式 4 tCLK 字节解码等待，采样 DMA 不插入 RDATA 命令。外部 U12 频率仍待实测，软件范围校验不等于测量 MCLK。

16 kSPS 原始数据约 432000 B/s，持续满包协议数据约 455111 B/s，另有 TCP/IP 和无线开销。512 样本跨核队列仅能缓存约 32 ms。Wi-Fi 吞吐、USB 同时运行及长时间稳定性必须实机验证，不能只凭 SPI 带宽预检宣称可无损长期采集。

## 网络连续性

动态配置复用已有停止通知和 START 生命周期回调。原始样本仍逐帧传给 Core 1，旧队列样本保持旧元数据；配置切换时旧包结束并补零，新采集启动使用新 stream_id。包内不混合配置，包头的 rate/gain/mode 对应所携带的样本。停止状态修改配置还没有新样本，直到 `g` 启动才生成新代次。

不会等待 TCP ACK、无线连接或跨核队列空位。停采时 ADS 本地在途/未取样本按原有策略计入 stopdiscard；网络背压和丢新样本策略保持不变。详见 [Wi-Fi 调试说明](WIFI_DEBUG.md) 和 [协议 V1](PROTOCOL_V1.md)。

## 验证与复现

`tests/test_usb_controls.c` 链接实际命令解析器、配置控制器、SPI 规划器和网络编码器，硬件驱动边界用可控替身注入成功/失败；覆盖所有合法参数、非法输入、溢出、分段/换行/退格、超长恢复、旧命令兼容、同值不重配、运行/停止路径、预检/配置/START 失败及网络配置分包。原有 C 协议/队列、ADS 全域符号扩展、Python 8 项测试同时运行：

```powershell
powershell -ExecutionPolicy Bypass -File tests/run_tests.ps1
& "$env:USERPROFILE/.pico-sdk/cmake/v3.31.5/bin/cmake.exe" --build build --parallel 4
& "$env:USERPROFILE/.pico-sdk/cmake/v3.31.5/bin/cmake.exe" --build build/no_wifi --parallel 4
```

配置命令见 Wi-Fi 文档：默认 `build` 为 Wi-Fi ON，`build/no_wifi` 为 OFF，SD/UART 均 OFF。固件分别为 `build/spi_dma.uf2` 和 `build/no_wifi/spi_dma.uf2`。维护源使用 `-Wall -Wextra -Werror`。

本次实际结果：ON/OFF 均构建成功，新增控制测试及全部既有测试通过。ELF text/data/bss 分别为 ON：341440/0/119404 字节，OFF：45964/0/14532 字节。新增静态命令解析状态使 BSS 增加 56 字节；不增加网络队列容量。

修改文件：`usb_commands.c/.h` 实现行解析；`ads1299_control.c/.h` 实现保存状态及配置提交；`ads1299.c/.h`、`ads1299_format.c/.h`、`ads1299_config.h` 实现预检、SPI 规划/应用及上限；`spi_dma.c` 接入命令、帮助和真实状态报告；`CMakeLists.txt` 添加源文件；`tests/test_usb_controls.c`、`tests/run_tests.ps1` 添加验证；本文与 ADS/Wi-Fi 文档更新说明。

实机步骤：

1. 内部测试模式依次设置全部七档采样率，查看实际 SPI/帧率、busy/qdrop/超时；逻辑分析仪检查每帧 216 个时钟及 DRDY 周期。
2. 每档增益执行一次，确认 CH1SET～CH8SET 读回一致；测试幅度变化要结合增益和实际输入范围判断。
3. `x` 停止后执行 `:rate 500`、`:gain 12`，确认仍停止；`g` 后才出现新数据。
4. 连续发送同值命令，确认 stream_id 不变化；改变参数确认旧包补零、新代次和正确元数据。
5. 输入错误值、超长行和退格，确认采集不中断；通过受控硬件故障验证写入失败保持停止且配置无效，不使用生产测量连接做故障注入。
6. Wi-Fi 接收与 USB 日志同时工作，逐档持续测试，尤其 16 kSPS；区分硬件采集丢帧、网络队满和日志丢弃。
